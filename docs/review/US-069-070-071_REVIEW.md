### Issues

#### [MEDIUM] #1: Test files missing `isValidating` in mock `useApi` return values
**Files**: All new test files (`EventFeed.test.tsx`, `PortfolioSummary.test.tsx`, `RiskGauge.test.tsx`) and modified tests (`PnLChart.test.tsx`, `PositionTable.test.tsx`)
**Issue**: All mock `useApi` return values cast `as ReturnType<typeof useApi>` but are missing the `isValidating` property required by SWR's `SWRResponse` type. This causes 48 TypeScript errors under `tsc --noEmit`. Although Jest tests pass at runtime (because mock objects work without the property), the type errors make `tsc` fail for the entire project.
**Fix**: Add `isValidating: false` to every mock return object, or change the cast to `as unknown as ReturnType<typeof useApi>` to suppress via double-cast. Better approach -- create a shared helper:
```typescript
function mockApi<T>(data: T | undefined, error?: Error, isLoading = false) {
  return {
    data, error, isLoading, isValidating: false, mutate: jest.fn(),
  } as ReturnType<typeof useApi>;
}
```
**Note**: This same pattern exists in pre-existing test files (KillSwitch.test.tsx avoids it by not using useApi). The new tests propagated the existing pattern. Recommend fixing all test files in a single pass.

#### [MEDIUM] #2: `StatusResponse` type missing `uptime_seconds` field
**File**: `/Users/100aniv/development/arbitrage_OMC/dashboard/src/types/index.ts:9-17`
**Issue**: `StatusResponse` does not declare `uptime_seconds`, yet `system/page.tsx:67` uses a type assertion hack: `(status as (typeof status & { uptime_seconds?: number }) | undefined)?.uptime_seconds`. The engine API likely returns this field but the type is incomplete.
**Fix**: Add `uptime_seconds?: number;` to the `StatusResponse` interface and remove the assertion:
```typescript
export interface StatusResponse {
  running: boolean;
  kill_switch_active: boolean;
  environment: string;
  execution_mode: string;
  strategy_count: number;
  position_count: number;
  connection_count: number;
  uptime_seconds?: number;  // <-- add this
}
```
**Note**: This is a pre-existing issue (only alignment changed in this diff), not introduced by this PR. Listed for tracking.

#### [MEDIUM] #3: Funding page history accumulation grows unbounded per-symbol
**File**: `/Users/100aniv/development/arbitrage_OMC/dashboard/src/app/funding/page.tsx:44-51`
**Issue**: The history slice limit is 50 entries total, but each poll adds N entries (one per exchange/symbol pair). With 8 exchanges and 12 symbols, each poll adds ~96 entries, meaning the "last 50" effectively holds less than one polling cycle. The cumulative calculation recomputes from the start of the array, so short history makes cumulative values less meaningful.
**Fix**: Increase the limit to accommodate multiple cycles (e.g., 500), or accumulate one entry per symbol per poll instead of per exchange/symbol. Alternatively, accept the current behavior as a rolling window of the most recent data points.

#### [LOW] #1: Duplicate rate computation in funding BarChart
**File**: `/Users/100aniv/development/arbitrage_OMC/dashboard/src/app/funding/page.tsx:215-218` and `241-243`
**Issue**: The average rate per symbol is computed identically in both the BarChart `data` prop and inside the `Bar` children (for Cell coloring). This means the same computation runs twice per render for 12 symbols.
**Fix**: Extract the bar data computation to a `useMemo` above the JSX:
```typescript
const barData = useMemo(() => symbols.slice(0, 12).map(sym => {
  const rates = exchanges.map(ex => data[ex]?.[sym]?.rate ?? 0);
  const avg = rates.reduce((s, r) => s + r, 0) / Math.max(rates.length, 1);
  return { symbol: sym, rate: parseFloat((avg * 100).toFixed(4)), avg };
}), [symbols, exchanges, data]);
```

#### [LOW] #3: GlobalHeatmap exchange name capitalization may not match grid keys
**File**: `/Users/100aniv/development/arbitrage_OMC/dashboard/src/components/GlobalHeatmap.tsx:55-57`
**Issue**: Exchange IDs from API are lowercased (e.g., `binance`), then capitalized via `id.charAt(0).toUpperCase() + id.slice(1)` to display names (e.g., `Binance`). The connection status lookup at line 135 uses `ex.toLowerCase()` to reverse this. This works for single-word names but would fail for multi-word exchange IDs like `binance_futures` (would become `Binance_futures`).
**Fix**: Store the original lowercase ID alongside the display name, or use a proper display name mapping. Current 7 exchanges are all single-word so this is not a live issue today.

#### [LOW] #5: `PerformanceTrend` useEffect missing cleanup for `lastSampleRef`
**File**: `/Users/100aniv/development/arbitrage_OMC/dashboard/src/components/PerformanceTrend.tsx:30-41`
**Issue**: The `useEffect` that samples WS data runs on every `data` change. The `lastSampleRef` correctly throttles to 5s intervals, but the effect has no cleanup. This is fine because refs don't need cleanup, but the `data` dependency means this effect fires on every WS message (every 1s), though it exits early via the timestamp check. Consider adding the sampling interval as part of a separate `setInterval` for cleaner separation.
**Fix**: Optional refactor -- use `setInterval` with `useRef` for the latest data instead of re-running the effect on every WS update.
