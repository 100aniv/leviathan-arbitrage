### [HIGH-1] 기준 자본 100,000 USDT 하드코딩

**File:** `engine/src/api/routes/portfolio.py:116,128`

```python
"equity": round(total_pnl + 100000, 2),  # base + pnl
"btc_benchmark": 100000,  # placeholder
```

**문제:** Shadow 경로(116)와 fallback 경로(128) 모두 `100000`이 고정값으로 들어간다.
- 계좌 초기 잔고가 $100,000이 아니면 equity curve 자체가 틀린 수치
- BTC benchmark도 항상 $100,000 flat — 수익률 비교 불가
- 실거래 전환 시 치명적 오해를 유발

**Fix:** `ctx.runtime_settings.get("initial_capital", 100000)` 또는 `_get_exchange_balances()`의 합계를 세션 시작 시 기록해 사용. BTC benchmark는 `BTC 시작가격 × (현재가 / 시작가) × initial_capital`로 계산.

### [HIGH-2] Calmar 비율 연율화 공식 오류

**File:** `engine/src/api/routes/portfolio.py:157-159`

```python
mdd = metrics["max_drawdown_pct"]   # e.g. 0.07 (= 0.07%)
if mdd > 0:
    metrics["calmar_ratio"] = round(metrics["total_pnl"] / (mdd / 100 * 100000) * 365, 2)
```

**문제:** `* 365`는 `total_pnl`이 **일별** PnL임을 가정한다. 그러나 `total_pnl`은 세션 전체 PnL (10분 Shadow면 10분치). 결과:
- 10분 세션, PnL=$21.10, MDD=0.07%: `21.10 / 70 * 365 ≈ 110`
- 실제 연율화 Calmar와 수백 배 차이 → 사용자 오판 유발

표준 Calmar = `annualized_return_% / max_drawdown_%`. 세션 경과 시간 없이 연율화 불가.

**Fix:** (a) `ctx`에 `session_start_ts` 저장, `elapsed_days = (now - session_start) / 86400` 사용해 `annualized_pnl = total_pnl / elapsed_days * 365`로 계산; 또는 (b) 다일 이력 데이터 부재 시 `null` 반환 + `"calmar_note": "requires multi-day history"` 추가.

### [HIGH-3] sharpe_ratio 항상 0.0 — 미구현

**File:** `engine/src/api/routes/portfolio.py:140,149-159`

```python
metrics = {
    "sharpe_ratio": 0.0,   # ← 초기화 후 절대 갱신되지 않음
    ...
}
# shadow 블록: total_pnl, win_rate, total_trades, max_drawdown_pct만 설정
# sharpe_ratio는 건드리지 않음
```

**문제:** 대시보드 Portfolio 페이지에 Sharpe Ratio 카드가 표시되나 항상 `0.00`. 사용자는 실제 Sharpe가 0이라고 오해한다. QUANT_MANIFESTO.md에 공식이 문서화되어 있음.

**Fix:** (a) snapshot에 `returns` 리스트가 있으면 `np.mean(returns) / np.std(returns) * sqrt(365)` 계산; 또는 (b) `"sharpe_ratio": null` 반환하고 대시보드에서 `null`을 `"—"`로 표시. 현재처럼 0.0 반환은 명백히 오해를 유발하므로 최소한 (b)를 적용해야 함.
