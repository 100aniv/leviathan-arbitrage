## Risk Mitigations (Addressing Winter's Concerns)

### Concern 1: Math formulas corruption
**Mitigation**: Round 4 has explicit checksum verification of lines 248-352 before and after edits.
No Round touches SSOT.md Section 4. Round 2 and 3 only touch engine/ files.

### Concern 2: Existing CircuitBreaker interference
**Mitigation**: The new PerStrategyCircuitBreaker is a SEPARATE class. The existing global
CircuitBreaker (`engine/src/risk/circuit_breaker.py`) is NOT modified. Both operate
independently as defense-in-depth layers.

### Concern 3: Per-strategy loss cap breaking existing trades
**Mitigation**: The default fallback is `max_single_loss_usd` ($50 from trading.json).
Only strategies with explicit entries in `per_strategy_loss_cap_usd` get different values.
Unknown strategy IDs automatically fall back to $50.

### Concern 4: Disabling strategies might affect test suite
**Mitigation**: `disabled_strategies` is only read at runtime via `.env` / `trading.json`.
Unit tests use their own fixtures and do not depend on runtime config.
Round 1 includes a full test suite run to verify zero regression.

### Concern 5: 1.5s freshness threshold too aggressive
**Mitigation**: The threshold applies ONLY to `_evaluate_futures_futures`. All other
strategies retain their existing freshness logic. If futures books are reliably fresh
(Binance/OKX/Bybit WS), 1.5s is conservative. The `last_update_time > 0` guard
(line 326) handles cold-start gracefully.

### Concern 6: SSOT_COMPLETE.md append before SSOT.md trim
**Mitigation**: Round 4 explicitly documents: "Phase S13 is new, no archival needed."
No content moves from SSOT.md to SSOT_COMPLETE.md in this phase. Future archival
