### What is Missing (the deliverables)

1. **TriangularScanner** -- A standalone Bellman-Ford graph scanner that detects ALL profitable cycles, not just hardcoded USDT->BTC->ETH. Must be depth-aware (use actual liquidity, not just top-of-book).
2. **RealDataSignalProducer** -- Encapsulates spot_futures, funding_rate, and triangular signal production using real market data. Replaces the inline `_evaluate_*` methods in ShadowMode.
3. **Shadow wiring** -- Connect RealDataSignalProducer to ShadowMode so `_on_orderbook` triggers real-data signals alongside the existing cross-exchange SignalGenerator.
4. **Integration tests** -- End-to-end verification that all signal types are produced from orderbook updates.

### Key Architectural Insight

Currently, ShadowMode's `_evaluate_multi_strategies()` calls `_evaluate_triangular()` and `_evaluate_futures_futures()` directly. The `_evaluate_spot_futures()` and `_evaluate_funding_rate_arb()` are called from `_funding_rate_loop()` (every 60s). This coupling means:
- Strategy logic lives in the mode orchestrator (wrong layer)
- Paper mode cannot reuse the same signal production
- No unit-testability without spinning up a full ShadowMode

The fix: extract all evaluation logic into `RealDataSignalProducer`, which both Shadow and Paper modes can use.

### US-019: TriangularScanner (Bellman-Ford)

**File**: `engine/src/core/triangular_scanner.py` (NEW)

**Interface Contract**:
```python
@dataclass
class TriangleCycle:
    exchange_id: str
    path: list[str]           # e.g. ["USDT", "BTC", "ETH"]
    pairs: list[str]          # e.g. ["BTC/USDT", "ETH/BTC", "ETH/USDT"]
    sides: list[str]          # e.g. ["buy", "buy", "sell"]
    prices: list[Decimal]     # execution prices (depth-aware)
    profit_pct: Decimal       # net cycle return - 1
    max_volume_usdt: Decimal  # bottleneck liquidity in USDT terms

class TriangularScanner:
    def __init__(self, min_profit_bps: Decimal = Decimal("10")) -> None: ...

    def on_orderbook_update(
        self,
        exchange_id: str,
        symbol: str,
        book: OrderBook,
    ) -> list[TriangleCycle]:
        """Synchronous. Returns profitable cycles found after this update."""

    def _build_graph(self, exchange_id: str) -> dict[str, dict[str, Edge]]:
        """Build -log(rate) weighted directed graph from all books on this exchange."""

    def _detect_negative_cycles(self, graph, start: str) -> list[list[str]]:
        """Bellman-Ford negative cycle detection. Returns cycles as currency paths."""

    def _calculate_depth_aware_profit(
        self, exchange_id: str, cycle: list[str]
    ) -> TriangleCycle | None:
        """Walk the cycle using actual orderbook depth, not just top-of-book."""
```

**Algorithm Details**:
1. Maintain per-exchange book cache: `_books[exchange_id][symbol] = OrderBook`
2. On each update, rebuild graph for that exchange (only if 3+ symbols exist)
3. Graph nodes = currencies (USDT, BTC, ETH, etc.)
4. Graph edges = trading pairs with weight = `-log(best_rate)`
   - For pair "ETH/BTC": edge BTC->ETH with weight `-log(best_ask)` (buy ETH), edge ETH->BTC with weight `-log(1/best_bid)` (sell ETH)
5. Bellman-Ford from each node that has USDT connectivity
6. Negative cycle = sum of weights < 0 = product of rates > 1 = profit
7. Depth-aware step: walk the cycle legs through orderbook depth levels, accumulating actual fill prices and tracking bottleneck volume

**Acceptance Criteria**:
- [x] Detects all 3-currency cycles on a single exchange (not just USDT->BTC->ETH)
- [x] Uses `-log(rate)` Bellman-Ford, not brute-force enumeration
- [x] Depth-aware: uses actual book levels, not just top-of-book `best_bid()`/`best_ask()`
- [x] Returns `max_volume_usdt` reflecting bottleneck liquidity
- [x] `min_profit_bps` gate before returning a cycle
- [x] Handles edge cases: empty books, single-level books, zero prices
- [x] Pure synchronous (no async) -- called from async context but does not need to be async itself
- [x] 10+ unit tests in `engine/tests/unit/test_triangular_scanner.py`

**Risk**: Bellman-Ford on dense graphs can be O(V*E). Mitigation: limit to currencies present in at least 2 pairs on the exchange (pruning orphan nodes). Typical exchange has 5-15 relevant currencies.

### US-020: RealDataSignalProducer

**File**: `engine/src/core/real_signal_producer.py` (NEW)

**Interface Contract**:
```python
class RealDataSignalProducer:
    def __init__(
        self,
        multi_signal_producer: MultiStrategySignalProducer,
        triangular_scanner: TriangularScanner,
        funding_rate_store: FundingRateStore | None = None,
        futures_exchanges: set[str] | None = None,
    ) -> None: ...

    async def on_orderbook_update(
        self,
        exchange_id: str,
        symbol: str,
        book: OrderBook,  # core OrderBook with best_bid()/best_ask()
        all_books: dict[str, dict[str, Any]],        # symbol -> exchange -> book
        futures_books: dict[str, dict[str, Any]],     # symbol -> exchange -> book
    ) -> list[Signal]:
        """Evaluate all real-data strategies for this orderbook update.
        Returns list of signals produced (may be empty)."""

    async def on_funding_rates_updated(
        self,
        rates: dict[str, dict[str, float]],  # exchange -> symbol -> rate
        books: dict[str, dict[str, Any]],     # for reference prices
    ) -> list[Signal]:
        """Called after FundingRateCollector.poll_once(). Evaluates funding rate arb."""
```

**Internal Methods** (extracted from ShadowMode):

| Method | Source | Signal Type |
|--------|--------|-------------|
| `_evaluate_triangular()` | TriangularScanner.on_orderbook_update() | `triangular` |
| `_evaluate_spot_futures()` | shadow.py:816-859 (extracted) | `spot_futures_basis` |
| `_evaluate_futures_futures()` | shadow.py:861-915 (extracted) | `futures_futures_spread` |
| `_evaluate_funding_rate_arb()` | shadow.py:990-1037 (extracted) | `funding_rate_arb` |

**Data Flow**:
```
OrderBook update
    |
    v
RealDataSignalProducer.on_orderbook_update()
    |---> _evaluate_triangular(exchange_id, symbol)
    |        |---> TriangularScanner.on_orderbook_update()

    |        |---> Compare futures prices across exchanges

```

## 6. Risk Areas and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Bellman-Ford perf on large graphs | High latency per orderbook update | Limit graph to currencies with 2+ pairs; skip rebuild if book count < 3 |
| Shadow.py extraction regression | Broken signal flow | Exact copy of logic; run `pytest -x` after each extraction |
| Depth-aware calc complexity | Incorrect volume limits | Test with multi-level books; compare to top-of-book-only baseline |
| Korean exchange stale data | False triangular signals on coinone/bithumb/upbit | TriangularScanner should inherit the staleness exclusion (Korean exchanges rarely have 3+ pairs anyway) |
| FundingRateStore race condition | Stale rates used for signal | FundingRateStore is single-threaded (asyncio); no actual race. Document that `on_funding_rates_updated()` should be called AFTER store update |
